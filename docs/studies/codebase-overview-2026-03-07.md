# CogLog コードベース確認メモ（2026-03-07）

## 1. docs/ 精読サマリ

- `DESIGN-v0.9.1` は CogLog を「窓サイズ1・上書き・不可逆（時間の矢）」のメタ認知ログとして定義している。
- `SPEC-TEST-v0.9.1` は、初期状態、write/read ラウンドトリップ、バリデーション、turn_id 単調増加、clear、`_schema` 自動付与、CLI/MCP 入出力、クロス言語互換までを網羅する。
- `SPEC-path-resolution-v0.9.1` は保存先の決定順序を仕様化しており、環境変数 `COGLOG_DIR` を優先する設計。
- `PROBLEMS-v0.9.1` と各 `PLAN-*` は、v0.9.1 時点での課題（パス解決、リリース整合、i18n、バージョン同期）と、段階的な是正方針を整理している。
- studies 配下は、CogLog の4軸を既存フレームワーク（5W1H/OODA/Kolb 等）と比較し、意図的な非採用軸（評価・正確性など）を明示する研究メモになっている。

## 2. コード全体の構造

- ルート README の通り、同一データモデルを複数言語（実用層 + 分析層）で実装しているモノレポ構成。
- 各実装は共通して、`read / write / clear` を CLI と MCP で提供する二層構造。
- データモデルは `_schema + turn_id + timestamp + layers + 4つの解釈フィールド` で統一されている。

## 3. 実装横断で確認した一貫点

1. **スキーマバージョン整合**
   - Python / Node / Rust / Go いずれも `0.9.1` を内部定数として持つ。
2. **バリデーション方針の整合**
   - `user/thinking/assistant` は非空必須、解釈層4項目は「文字列必須・空文字許容」という設計が共通。
3. **保存先の優先順位整合**
   - 少なくとも Python・Rust・Go・Node で `COGLOG_DIR` 優先の経路決定が実装されている。
4. **MCP ツール境界の整合**
   - `coglog_read / coglog_write / coglog_clear` の3ツール公開が共通で、I/O 契約が揃っている。

## 4. 実装方式の違い（意図的差分）

- Java/C++ は依存最小化のため、JSON処理を外部依存に寄せずに実装している（手書き or 最小ライブラリ同梱）。
- Rust は `coglog-core` を中心に CLI/MCP を分割し、型安全と責務分離が明確。
- Bash/Haskell/Common Lisp は「分析層」として、設計思想（POSIX還元・純粋/不純分離・homoiconicity）を照らす位置づけ。

## 5. 現時点の所見

- docs と実装の主契約（データ形状、必須/任意、窓サイズ1、上書き、MCP 3ツール）は概ね整合している。
- ただし docs 側にも記載がある通り、**課題は「仕様不足」より「多言語での同期運用（バージョン、テスト、リリース手順）」に寄っている**。
- 今後の保守コスト観点では、仕様ドキュメントよりも「クロス言語自動検証（同一fixtureでの read/write 互換テスト）」の強化が最優先。
